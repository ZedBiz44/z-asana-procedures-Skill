# Brief formats

Replace bracketed input fields before release. These are writing formats, not live Asana project/task templates. Use the shorter format when it fully describes the work.

## Project brief

- Purpose: [business problem and beneficiary].
- Outcome and success measures: [deliverables, acceptance, and separately measured business results].
- Scope: [included work and exclusions].
- People: [project owner, coordinator, intended contributors, reviewer, approver].
- Authority: [approved work and decisions still required].
- Timing: [start window, finish, milestones, and fixed commitments].
- Working method: [section pattern, stage source, useful views, update cadence].
- Resources: [approved brief, SOP, working folder, technical record].
- Acceptance and handover: [checks, decision-maker, ongoing owner].

## Main-task description

- Working source: [exact folder/file].
- Final result and proof: Pending completion.
- Required result: [deliverable, format, quantity, audience, destination].
- Why this matters: [business purpose].
- Please complete: [required actions or phases, matching relevant subtask sections].
- Inputs and limits: [approved sources, constraints, work to preserve].
- Timing and wait conditions: [handoffs, prerequisites, approval owner].
- Done when: [observable checks and required acceptance].
- Return: [exact file/link/check result and where to post it].

Keep the intended owner in planning until readiness passes. Native assignee and date fields hold the final assignment details.

## Short task

Action: [one change]. Reference: [approved source]. Done when: [check]. Save or post here: [destination]. Authority or limits: [if relevant].

Example: Replace the contact-page phone number with the number in the approved contact record. Update the visible number and click-to-call link. Keep other content unchanged. Done when both match and the link opens the correct number on mobile. Post the page URL and test result on this task.

## Subtask

Using [source], produce [specific result] for [main outcome]. Follow [requirements]. Save it in [destination] and post [exact proof] here. Done when [check]. Wait for [prerequisite/decision] before [restricted action].

## Review request

[Reviewer], please review [exact version/link] against [acceptance checks] by [actual agreed date]. Post acceptance or specific corrections on [task]. [Delivery owner] will make the corrections. [Restricted action] must wait for [named approval].

## Problem or decision request

[Person], [specific work] cannot continue because [cause]. I checked [attempts/proof]. Please provide or decide [exact need] by [relevant agreed date]. This affects [result or deadline]. I can continue [independent work]. The waiting step can resume when [condition].

## Finish report

- Delivered: [result and location].
- Editable source: [link].
- Checked: [specific checks and proof].
- Accepted: [reviewer/decision where required].
- Remaining: [none, or agreed exception and owned follow-up].
- Next owner/action: [handover if needed].

For setup-only work, report “Ready and assigned” or “Prepared but not released,” not “Business work complete.”
